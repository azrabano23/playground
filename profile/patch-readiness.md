# Patch readiness

Before opening the unsubmitted patches as pull requests, each one that can be built in a plain
Linux container was checked the way a maintainer would check it:

1. run the tests the patch adds — they must pass
2. revert **only** the non-test files, keep the tests — they must now fail

Step 2 is the part that matters. A test that still passes once the fix is removed demonstrates
nothing, and a maintainer will say so.

## Needs attention before sending

**`exchange_calendars` `fix-xkrx-empty-observance`** — the fix is right, but its test cannot fail
on a current pandas, so it does not guard anything on the project's CI.

The patch guards `_apply_observance` with `not dates.empty`, and its own comment gives the reason:
on pandas < 2.1 `DatetimeIndex.map` first tries handing the whole index to the mapper, so an empty
index reaches the observance as a `DatetimeIndex` instead of a `Timestamp`. That `.map` behaviour
is gone in pandas ≥ 2.1, so on pandas 3.0.6 the added test passes with the fix **and** with the
fix reverted — confirmed against the reverted file, not inferred.

The fix is still worth sending: `pyproject.toml` declares `pandas>=1.5.0`, so the affected versions
are supported. But no test can distinguish the two states on a modern pandas, because the buggy
behaviour does not exist there. Two honest options:

- say in the pull request that the regression reproduces only on pandas < 2.1, and that the test is
  a guard rather than a reproduction, or
- mark the test so it only asserts the old behaviour under `pandas < 2.1`

What should not happen is sending it as-is with no explanation: a maintainer runs it on current
pandas, sees it pass either way, and reasonably asks what it proves.

## Reproducing

For a pure-Python patch, from a clone of the fork at the patch branch with depth ≥ 2:

```sh
python3 -m pytest <the patch's test files> -q          # expect pass
git checkout HEAD~1 -- <the patch's non-test files>
python3 -m pytest <the patch's test files> -q          # expect fail
git checkout HEAD -- <the patch's non-test files>
```

A shallow `linearmodels` checkout needs a stub `linearmodels/_version.py`, since the real one is
generated by setuptools_scm from tags a shallow clone does not fetch.
