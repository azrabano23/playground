**Title:** DOC: Document BCa and studentized caveats for block bootstraps

**Body:**

xref #801. This is a docs-only change and doesn't close the issue.

For the time-series bootstraps, `conf_int` currently behaves in two ways that aren't documented:

- `method="bca"` estimates the acceleration with a leave-one-out (IID) jackknife. `CircularBlockBootstrap`, `MovingBlockBootstrap` and `StationaryBootstrap` inherit `_bca_acceleration` from `IIDBootstrap`, so `a` is the same as for the IID bootstrap.
- `method="studentized"` without `std_err_func` builds the nested bootstrap with `clone()`, which reuses the outer `block_size`.

This PR adds a short paragraph to the `conf_int` Notes and two `.. note::` blocks in `doc/source/bootstrap/confidence-intervals.rst`. There is no code change. The methodological changes (a block jackknife option and an inner block size argument) are proposed in #801 so they can be discussed first.

I checked the behaviour by spying on `_loo_jackknife` and `clone`. All four bootstrap classes call `_loo_jackknife(nobs=n)` and get identical `a`. With `CircularBlockBootstrap(20, x)`, the only inner block size used is 20.
