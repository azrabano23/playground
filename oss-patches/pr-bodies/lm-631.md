Closes #631 (partially; see the open questions below).

**What's going on**

`PanelOLS` results show three F statistics. With `cov_type="robust"` or `"clustered"`, two of them come out exactly the same as the unadjusted fit:

```python
from linearmodels.datasets import wage_panel
from linearmodels import PanelOLS
d = wage_panel.load().set_index(["nr", "year"])
m = PanelOLS.from_formula("lwage ~ 1 + hours + married + union + EntityEffects", d)
```

| cov_type   | f_statistic | f_statistic_robust | f_pooled (main) |
|------------|-------------|--------------------|-----------------|
| unadjusted | 68.0303     | 68.0303            | 7.9732          |
| robust     | 68.0303     | 67.5784            | 7.9732          |
| clustered  | 68.0303     | 44.2446            | 7.9732          |

- `f_statistic_robust` is the robust Wald F. It already uses the chosen covariance, and `test_simulated_against_stata.py::test_f_stat` checks it against Stata's `e(F)`.
- `f_statistic` is documented as the classical homoskedastic F. The robust version is reported next to it, so I left it alone.
- `f_pooled` (the "F-test for Poolability" in the summary) is an RSS-based F. Its docstring already says it's only correct under homoskedasticity, but it's still printed under robust or clustered covariances with no qualification. That's the number that looks "not updated". Stata handles this by not reporting it: in the reference output shipped in `linearmodels/tests/panel/results/stata-panel-simulated-results.txt`, `F_f` is empty for every `xtreg ..., fe vce(robust)` and `fe vce(cluster firm_id)` run, and filled in only for `vce(conventional)`.

**Change**

- `PanelOLS.fit` now returns an `InvalidTestStatistic` for `f_pooled` whenever the covariance estimator isn't homoskedastic (robust, clustered, kernel/Driscoll-Kraay, ac). The reason text tells the user to refit with `cov_type="unadjusted"`. The summary already leaves out non-finite poolability stats, so the line disappears there too. Results under `cov_type="unadjusted"` are unchanged.
- Updated the `f_pooled` docstring to match.
- Docs: `doc/source/iv/introduction.rst` still listed the IVGMM weight type as `'cluster'`. The accepted key is `'clustered'` (see `WEIGHT_MATRICES`). This was the one remaining spot from the docs part of #631; the docstrings were already fixed in ad5b964.

**Tests**

- `test_simulated_against_stata.py::test_f_pooled` used to skip when Stata's `F_f` was missing. It now asserts that linearmodels returns an `InvalidTestStatistic` in exactly those cases (FE with robust or clustered covariance).
- New `test_panel_ols.py::test_f_pooled_robust_cov`, parametrised over robust, clustered-by-entity and kernel. It checks that `f_pooled` is invalid/NaN and not in the summary, that `f_statistic` is unchanged, and that the unadjusted fit still reports poolability.
- Before the fix: `pytest linearmodels/tests/panel/test_panel_ols.py linearmodels/tests/panel/test_simulated_against_stata.py -k f_pooled -p no:randomly` gave 66 failed, 24 passed, 33 skipped. After the fix: 90 passed, 33 skipped.
- `pytest -n 4 -p no:randomly linearmodels/tests/panel/{test_simulated_against_stata,test_results,test_formula,test_panel_ols}.py`: 2208 passed, 49 skipped, 47 xfailed
- `pytest -n 4 -p no:randomly` on `test_between_ols.py`, `test_cluster_input_formats.py`, `test_firstdifference_ols.py`, `test_model.py`, `test_panel_covariance.py`, `test_pooled_ols.py`, `test_random_effects.py` and `test_fama_macbeth.py`: 597 passed
- `flake8 linearmodels`, `black --check linearmodels`, `isort --check linearmodels`, `ruff check linearmodels`: all clean.

**Open questions for review**

1. Is returning `InvalidTestStatistic` too strong a change? If you'd rather keep the number available, the alternative is to keep computing it and just label it as homoskedastic, e.g. rename it to `"Pooled F-statistic (homoskedastic)"` and print "F-test for Poolability (homoskedastic)" in the summary when the covariance isn't unadjusted. I went with the Stata behaviour, but I'm happy to switch.
2. For clustered covariances, Stata and statsmodels use `F(k, G-1)` for the robust model F (Stata's `df_r` is 999 for the 1000-firm clustered runs in the reference file). linearmodels uses `F(k, df_resid)`. The statistic itself already matches Stata, so only the p-value differs, and only when `debiased=True`. I didn't change this here, because the t-test p-values also use `df_resid`, and switching only the F would make F and t inconsistent. Would you want a follow-up that uses `G-1` (min over cluster dimensions) for both?
3. The first "F-statistic" row in the `PanelOLS` summary is still the homoskedastic one under robust or clustered covariances. Should the label say "(homoskedastic)" when a non-default covariance is used?
